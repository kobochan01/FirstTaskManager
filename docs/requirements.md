# 要件定義書

## 1. プロジェクト背景・目的

本プロジェクトはプログラミングスクールの課題として作成するWebアプリケーションである。
Trello風のタスク管理アプリを自力で設計・実装することを通じて、以下の学習を目的とする。

- Reactを用いたコンポーネント設計とstate管理の習得
- ドラッグ&ドロップなどのインタラクションの実装経験
- localStorageを用いたクライアントサイドのデータ永続化の理解
- 要件定義から実装までの開発プロセスの体験

## 2. 機能要件

ユーザーが操作できる機能の一覧とユースケースをまとめています。
ボード・リスト・カードの作成・編集・削除、ドラッグ&ドロップ移動、ラベル・期限日の管理、localStorageによるデータ保存が対象です。

→ [機能要件ドキュメントを見る](./functional-requirements.md)

---

## 3. 非機能要件

### 対応ブラウザ
- Google Chrome（最新版）
- Microsoft Edge（最新版）
- PC表示のみ（モバイル・タブレット対応なし）

### 性能要件
- 画面の初期表示：体感で問題なく動作すること
- ボード数：上限なし
- リスト数：1ボードあたり10件まで
- カード数：1リストあたり100件まで
- localStorageの容量制限（約5MB）の範囲内で動作すること

### レスポンシブ対応
- PC表示のみ（モバイル・タブレット対応なし）
- 対象画面幅：1024px以上

### セキュリティ

**フェーズ1**
- 個人利用のためログイン・認証機能は不要
- localStorageに保存するデータに個人情報・機密情報は含まない
- ユーザー入力値をそのままHTMLに埋め込まない（ReactのデフォルトエスケープによりXSSを防ぐ）

**フェーズ2**
- SQLインジェクション対策、API認証、HTTPS化など（詳細は実装フェーズで追記予定）

## 4. 画面設計

アプリの画面構成と操作フローをまとめています。
3つの画面（ボード一覧・ボード詳細・カード詳細モーダル）の遷移図と、各画面のレイアウトをワイヤーフレームで定義しています。

→ [画面設計ドキュメントを見る](./screen-design.md)

---

## 5. データベース設計

データの構造とテーブル間のリレーションをまとめています。
boards・lists・cards・labels・card_labels の5テーブル構成で、フェーズ1のlocalStorage実装からフェーズ2のDB移行をスムーズに行えるよう設計しています。

→ [データベース設計ドキュメントを見る](./database-design.md)

---

## 6. 技術スタック

各フェーズで使用する技術をまとめています。
フェーズ1はReact + localStorageのフロントエンド完結構成、フェーズ2はNode.js + Express + PostgreSQLによるバックエンド・DB構成を予定しています。

→ [技術スタックドキュメントを見る](./tech-stack.md)
